# 有限模型规划

当前接入 DeepSeek 官方 HTTPS API，默认模型 `deepseek-flash`，也可在后端启动时选择 `deepseek-v4-pro`。
不使用 Agent 框架、任意 SQL、模型工具调用或向量检索。模型仅产生参数草稿；正式答案仍由确定性事实和固定模板产生。

## 启动与使用

默认 `python scripts/serve_api.py` 不调用模型，即使环境中已有密钥也不会自动启用。
在操作系统的用户环境变量中配置 `DEEPSEEK_API_KEY`，重新打开能继承该变量的终端后运行：

```shell
python scripts/serve_api.py --enable-model
# 可选后端型号；切换配置后重新创建草稿和计划
python scripts/serve_api.py --enable-model --model deepseek-v4-pro
```

不要在网页、源码、命令行参数或截图中填写密钥。没有读取 `.env`、搜索密钥或自动切换服务商的行为。
启用后按 DeepSeek 的实际用量计费；一次用户提交最多发出一次推理请求，失败没有隐藏重试。
入口位于“查询计划预检 → 自然语言规划”。表单草稿仍可使用。

可用示例：

> 截至 2026-09-07T00:00:00Z，列出 LOT-0001 的全部可见作业。

流程为“理解问题 → 核对模型草稿 → 生成服务端范围卡 → 查看完整成员和覆盖 → 显式确认 → 执行 → 校验事实 → 正式发布”。
理解问题本身不查询业务表、不确认、不执行、不发布。生成范围卡也不代表确认。
编辑问题会清除旧草稿/范围/结果；在途响应通过请求守卫丢弃。编辑或离页不撤销已经发出的、可能已计费的模型调用。

## 有意收窄的语言范围

- 单个确切、原文中出现的 `LOT-…` 和单个规范 UTC 字面值 `YYYY-MM-DDTHH:MM:SSZ`。
- 时间为“截至、含边界”；明确的“之前/早于/before/不含边界”不支持，不静默转换成含边界查询。
- 只列当时已知且已开始的全部作业，不按 PASS/FAIL、设备、关卡或 Top N 筛选。
- 缺项和多个不同 LOT/时刻由固定模板要求补充；日期、现在、昨天、本地时区不会被猜成 UTC。
- 仅支持登记的有限中文/英文完整句式，服务端必须匹配整句话；不是任意自然语言或多语言翻译。中文支持“截至 UTC，列出 LOT 的全部/所有/完整/全量可见作业”及已登记的参数顺序、可见性说明；英文支持 `List all operations for LOT as of UTC.`、`List complete operations ...`、`List every operation ...` 和 `Show the complete operation inventory of LOT as of UTC.`。
- 完整句式及允许的重复范围/空清单说明定义在 `inventory_language.py`；不通过删除未知后缀、注释、引号或 HTML 来制造匹配。未知附加内容返回固定 `QUESTION_FORM_NOT_SUPPORTED` 澄清，不发模型请求；仅给 LOT/UTC 并说“看一下”仍是 `INTENT_UNRESOLVED`。
- 对已注册的否定、排除/隐藏、质量、子集、追溯、比较或写入请求，服务端签发带原因的 unsupported，不改查清单。关键词只用于分类拒绝；未命中拒绝词也必须通过整句语法。
- 精确前缀“不是追溯；”或“不是追溯，也不是质量判断；”可接受支持的完整清单句式；仅这两种明确免责声明不会误触追溯/质量拒绝。任意否定句、法语等其他语言或未登记改写可能保守澄清，用户须重新完整表述原意，系统不能擅自删减要求。
- 这不是多轮聊天。补充信息通过修改完整问题并新建草稿进行；不发送历史消息。

能力检查是有限句式规则，可能误拒未登记的正确表达，不能证明任意自然语言已被完全理解。
含附加指令的注入文本也保守拦截；不再仅凭其中出现了正常清单前缀就调用模型。
草稿与正式范围卡必须让用户审查，不能用相同 hash 宣称模型已经理解正确。

## 结构化输出与状态归属

`model_contracts.py` 保存提示词 `lot-planner-1` 和严格 Schema。模型只允许三个必需字段：

```json
{"intent_key":"lot_operation_inventory","lot_id":"LOT-0001","as_of":"2026-09-07T00:00:00Z"}
```

模型可以提出 `intent_key=unresolved`，但不能直接签发任何页面状态。
通过同一整句语法的请求（包括 complete/every/完整/全量）被模型放弃时一律记为 MODEL_PROTOCOL_ERROR；真正未解或未登记句式在推理前使用固定阻塞问题。
缺失值只允许 null，不允许猜测。ready 候选的实体/时刻必须分别等于原文唯一字面值，改变就拒绝。
未知字段、模型自由标题/警告/结论/SQL/claims、重复 JSON 键、非 UTF-8、截断、空输出和工具调用均拒绝。
JSON mode 只是服务商传输提示，本地仍执行严格校验。原始模型文本和思考过程不进入 UI 或导出。

模型请求只发送固定系统提示词与本次原话的 JSON 数据对象，不发送数据库行、业务结果、成员列表或历史会话。
关闭流式响应；页面只显示服务端固定进度和合格草稿，不先展示模型原始流。

## 服务端状态与绑定

以下接口都在现有 HttpOnly/SameSite 会话及 Host/Origin 检查下：

| 接口 | 行为 |
| --- | --- |
| GET `/api/v1/query-plans/nl/config` | 只返回启用状态、服务商、模型名及固定说明，无密钥 |
| POST `/api/v1/query-plans/nl/proposals` | 只收 `{question}`，签发 ready / needs_clarification / unsupported，始终 `answer_published=false` |
| GET `/api/v1/query-plans/nl/proposals/{id}` | 核对会话、摘要、权限、期限、原契约束和配置后读取 |
| POST `/api/v1/query-plans/nl/proposals/{id}/preflight` | 只收 `{proposal_digest}`；从已保存草稿取参数，生成原有范围卡 |

客户端和模型均不能重传 endpoint/key/model/工具或确认参数。草稿限 2000 字符、有效期 1800 秒。
生成范围卡有原子、幂等映射；再次点击返回同一原始卡。卡片后来被修改时，旧草稿不能静默引用新版卡，必须新建草稿或走显式表单修订。
预检卡保存模型调用来源；其内容摘要和确认计划保持不可变。下游仍执行原有四前置和 G1–G4，草稿 ID/摘要不是独立授权。

契约束冻结提示词、Schema、能力及澄清规则代码、适配实现、模型名、端点和非敏感推理配置。
密钥不进入束或 API；API Key 的轮换不作为业务语义。供应商若静默更换同名模型权重，本程序不能证明权重未变，
只能记录请求型号和返回型号；模型输出本身不成为事实。

## 调用账本、预算与错误

`<database>.plans.sqlite3` 保存 `nl_calls`、`nl_proposals`、`nl_adoptions_v1`。
调用前先写入 running 记录，不能写入时不发推理请求；完成/失败后分别保存终态、起止时刻、
问题/提示词/Schema/响应摘要、请求与返回型号、实际 token 用量（若已取得）及固定错误码。
不保存密钥、Authorization、完整 HTTP 请求或原始模型正文。草稿保存用户原话用于核对。
进程在调用中崩溃可能留下 running 诊断记录；不会自动重发或自动恢复收费请求。

每个服务进程最多一个推理请求，在忙时返回 MODEL_BUSY。固定官方 HTTPS 端点，使用系统证书验证；
不接受客户端 URL、不跟随重定向，也不继承代理环境变量。预算为 400 输出 tokens、64 KiB 响应，配置网络超时 30 秒；
按剩余时间收取响应。操作系统 DNS 等底层阻塞不保证可精确在 30 秒内强制回收；未作强杀或慢速网络的真实故障验收。
模型预算与后续证据执行的 5/15 秒预算是不同阶段。

认证、限流、上游错误、网络错误、超时、响应超限和协议错误均使用固定消息，不回显供应商响应或本机路径。
失败不生成可用范围卡或正式答案；手动重试是一次新的显式请求，可能再次计费。

`Publication.model_output_used=false` 表示正式答案渲染不使用模型自由文字，不表示前面的草稿阶段没有调用模型。
当前能力版本为 `nl-planner-3`。测试覆盖固定句式、结构化协议、模型误拒与范围不一致等受控情形，见 [测试说明](testing.md)。有限语料和历史真实调用不能证明任意语言可靠，当前语法版本未做新的付费模型复测。
