# 确认后证据执行

仅支持 `lot_operation_inventory`：一个确切 LOT 截至显式 `as_of` 的全部可见作业。
没有模型、任意 SQL 或质量处置权限。执行结果是可核验的源证据及账本，
`answer_published` 始终为 `false`；事实注册与语义引用已由 [事实层](fact-registry.md) 承接，最终固定答案由独立的 [发布层](answer-publication.md) 签发。

## 调用与状态

端点前缀 `/api/v1/query-plans`，使用原有 envelope、随机会话、Host/Origin 与 no-store 约束。

| 方法及路径 | 输入 / 行为 |
| --- | --- |
| POST `/confirmed/{id}/execute` | 严格 JSON `{scope_hash}`；不能自带实体、来源、条件、预算、证据或路径 |
| GET `/executions/{id}` | 读取当前执行状态、调用与尝试账本及可访问的证据 |
| POST `/executions/{id}/cancel` | 严格空对象 `{}`；请求取消不是终态，须继续读取确认 |
| GET `/executions/{id}/export` | 实际 JSON 附件：执行视图、全部已取得结果、SourceResult 和 ExecutionRecord JSON Schema |

状态：`queued → running → completed / failed / cancelled`；重启恢复可进入 `interrupted`。
只有两项必需查询全部成功、最终前置重验通过且终态写入成功，才可持久标为 completed。
空作业列表可以完整成功；来源故障不会转为空列表。HTTP `ok=true` 表示成功读取执行记录，
须继续看 `state`、`execution_complete`、`state_persisted` 和访问状态。

每个确认计划只产生一个执行；重复提交复用同一账本，不增加查询或尝试。
失败执行不自动重启；需要重新查询时应重新生成、审查并确认计划。
网页当前手动刷新；切页/编辑会丢弃旧页面响应，但不会取消服务端工作。

## 冻结执行图与预算

`lots → operations` 为不可选的必需 DAG。所有查询参数只取自持久的已确认计划，
执行前、来源返回后、重试前、最终提交时重验权限、发现/成员、覆盖、快照和精确契约束。
首版每个来源一次取回完整小样本集合；超大响应失败关闭，不截断为成功。

| 参数 | 固定值 |
| --- | --- |
| 每次尝试预算 | 5 秒，单调时钟 |
| 执行总预算 | 15 秒，跨来源与重试共用 |
| 每个逻辑调用尝试上限 | 2 |
| 可重试错误 | 仅 `SOURCE_BUSY`（worker exit 75）；其他错误和超时不重试 |
| 源响应上限 | 1 MiB，超限拒绝 |
| 取消/截止检查周期 | 最多约 50 ms 一次，另加终止回收/存储开销 |

每个尝试在独立、只读 Python 子进程中执行；没有 Shell 或可执行插件。
正常、取消和超时返回前会回收该子进程。当前固定 worker 不创建后代进程；
这不是通用子进程沙箱或无限输出防护。返回大小上限在受信 worker 输出收集后检查，
不承诺适用于任意不受信进程。持久化和回收可额外等待，不承诺 HTTP 终态墙时小于 15 秒。

Schema 定义位于 `evidence_execution.py` 的严格 Pydantic 模型，保存及读取账本均验证。
预算、DAG、模型定义、执行器、worker、依赖版本和实际 UI 文件纳入原有内容寻址契约束；
修改代码/构建后须重启 API，旧束不可用时停止，不能把新实现冒充旧束。

## 证据与完整性

工作进程的 JSON 输入和输出均使用二进制管道显式 UTF-8 编解码，不依赖系统默认文本编码。
中文、emoji 字段及非 ASCII 文件路径有真实工作进程回归；见 对抗验收说明。

保存 request/execution/plan/scope 身份、快照和 manifest 摘要、集合版本、契约束、
稳定逻辑调用 ID、不同的尝试 ID、真实 UTC 开始/结束、失败代码和回收状态。
证据只接受当前计划对应来源、实体、时刻和全部规范行，与已验证快照独立比较；
同计数的换实体、丢行并缩小计数、额外字段或错误类型均不能成功。
证据摘要覆盖整个绑定对象；不把其他执行的旧证据当本次结果。

账本分别列出 `completed_scope`、`failed_scope`、`not_attempted_scope`。
已完成子范围可以保留原始证据，但不产生整个请求范围的质量结论、比例或排名。
权限撤销后整个执行端点拒绝访问；覆盖/束等前提不再成立时，仅提供诊断视图，
移除证据正文并将视图 `execution_complete` 置 false。历史状态仍保留，不伪装成新查询。

## 持久化、故障与边界

记录在 `<database>.plans.sqlite3`，不改业务 SQLite 或输入文件。
先提交 queued，再启动线程；每次尝试开始、结束及终态分别持久化。
终态写失败且故障持续时，本进程只能提供内存中的 failed 视图，
明确 `state_persisted=false`；重启后遗留的 durable running/queued 标为 interrupted，不重放。
控制库完全不可读时 HTTP 503，不假报终态完成。

仅支持一个 API 进程使用该控制库；不能启动多个 worker、热重载或并行实例共享控制库。
重启恢复不会声称已经确认崩溃前子进程回收：相关 attempt 标为未知。
本轮恢复测试构造了崩溃遗留记录后重建服务，未做真实 API 强杀/断电、满盘或多实例测试。
真实测试子进程的 5 秒截止与页面取消已执行并核对回收。
源快照/契约预检使用本地受信文件读取，当前没有对所有文件系统读取设置独立可中断超时。

同参数重试与耗尽、局部成功、真实子进程截止/取消/回收、漏行、虚拟时钟总预算、
执行中覆盖/束撤销、重启账本恢复、终态写入失败和存储篡改。
保留原有后端及前端守卫回归。浏览器核验实际确认→执行→状态→下载和取消→下载，
不据此声称 T01–T26 全部完成或最终答案已可发布。
