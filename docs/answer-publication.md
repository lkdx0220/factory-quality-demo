# LOT 作业清单答案与 G4

只发布 `lot_operation_inventory`：一个已确认 LOT、显式 UTC 历史时刻下的全部可见作业。
正式答案渲染不使用模型自由文字，不输出产品合格、通过率、根因或处置建议。`verified_answer` 表示当前范围的答案证据校验通过。可选模型仅用于上游草稿，见模型规划说明。

## 制品与发布流程

先完成范围预检、用户确认、证据执行、事实注册及 G3 引用校验，再显式生成正式答案。
预检、执行、事实和校验收据仍各自是 `answer_published=false` 的中间制品。
只有独立的 Publication 是 `answer_published=true`。界面用阶段记录区分这些状态。

发布请求只含 `fact_set_digest`、`validation_id`；事实集 ID 在路径中。
不接受客户端标题、摘要、建议、警告、状态、证据、模板或范围。
所有业务事实由服务端已有事实集产生；查询时刻来自已确认范围，发布时间来自服务端执行时钟，二者分开。

服务端在共享策略锁及控制库事务中完成：

1. 重验原精确契约束、发现完整性、可读成员归属、快照和覆盖、权限及有效期。
2. 重建证据和必需事实（G1/G2），核对指定已持久化、同绑定、完整且 accepted 的 G3 收据。
3. 用固定模板输出全部七项摘要及每个作业的七项字段，核对完整 rendered/required 身份集合。
4. 渲染后再次检查资格，持久化不可变 Publication；提交失败不能返回成功。

后续读取、完整明细和下载也重验上述资格、当前证据、绑定收据、内容摘要及精确模板重建结果。
数据库文档即使重新计算摘要，也不能悄悄更换标题、删行或改变必需事实。
不能将所有故障简单映射成空作业：零行成功可以发布七项摘要，依赖失败则不能发布。

同一会话、事实集和收据重复发布复用同一制品。制品绑定特定 accepted 收据；之后另一候选被拒不会改写旧收据，
也不能用新的 rejected 收据签发答案。每次仍核验源事实及当前资格。

## 受控展示

标题、标签、说明、列名由 `publication_templates.py` 定义；Schema 在 `publication_contracts.py`。
源值、已确认范围参数和注册派生值分开标记。所有文本经 React 文本节点展示，不使用 HTML 注入。
数据库原文是数据，不能成为系统指令或质量结论。用户原话仍只在计划区以来源标签展示，不进入答案标题或摘要。

答案必须直接展示 LOT、历史截止、全量作业数、成员摘要/完整性、排除数及质量指标不适用说明。
作业预览固定最多三条并注明展示/总数；完整入口和 JSON 附件包含全部作业字段及事实来源链。
完整性分别说明执行完整、质量证据不适用和完整明细可访问，不能用作业清单冒充质量检验。

当前可选 `/nl/proposals` 通道支持服务端固定澄清及 unsupported，模型仅提供受限草稿；不提供聊天历史或流式接口。
必填字段错误仍返回固定 HTTP 参数错误，不能假造模型澄清；有限句式和状态口径见 [模型规划说明](model-planning.md)。
发现缺口仍显示实际预检 incomplete；执行故障、取消和进度来自实际账本的固定状态模板，不能签发正式答案。
发布区错误只显示固定说明与受限错误码，不回显异常消息、原始请求或模型文字。
新增或扩展模型相关通道仍须按 SPEC 逐项验收，当前有限通道不能标为所有意图和输出的完整覆盖。

## 接口

前缀 `/api/v1/query-plans`；全部保留 `{ok, synthetic, data/error}`，会话归属、Host/Origin、no-store 和未知字段检查。

| 方法 / 路径 | 内容 |
| --- | --- |
| POST `/fact-sets/{id}/publish` | 严格 `fact_set_digest` 和 `validation_id`；签发/复用答案 |
| GET `/publications/{id}` | 重核资格，返回七项摘要、三条预览及完整入口 |
| GET `/publications/{id}/members` | `publication_digest` 必填；offset 默认 0、范围 0–100000；limit 默认 10、范围 1–100 |
| GET `/publications/{id}/export` | 实际 JSON 附件 `verified-lot-inventory.json`；含完整答案、全部作业、绑定事实、收据、Schema |

只有 members 接受分页查询参数；版本错误停止，其他接口额外参数拒绝。模型不获得自动签发权限。
API 的 `ok=true` 只表示操作成功；正式答案还必须为 `status=verified_answer`，不能由中间制品推定。

Publication 摘要为不含 `publication_id/publication_digest` 的文档规范 JSON SHA256；ID 为 `pub-` 加此摘要。
存储外层另校验完整文档摘要及 SQL 身份，最终还与当前精确模板重建结果逐项比较。
这些校验不是抗数据库管理员伪造的数字签名，也不证明模型理解用户原意或现实采集无遗漏。

## 有效期与部署边界

沿用计划 1800 秒有效期和本机单 API 进程约束；不延长到新一轮有效期。
页面在服务端给定期限到达时清除正式答案；任何后续请求失败也清除答案、明细与导出预览。
页面显示最后一次请求核验的结果；没有推送撤销机制，已发送内容或已下载文件无法追溯撤回。
时钟不准会影响客户端清除时机，但服务端所有后续请求仍使用服务端时钟判定。

契约束包含实际 Python、前端源码/构建物、依赖与输出政策；升级后原束不可用则需新计划，不静默套新模板。
更广的意图、真正模型评测、跨平台、满盘/强杀以及 T01–T26 全类验收不由 的限定回归代替。
